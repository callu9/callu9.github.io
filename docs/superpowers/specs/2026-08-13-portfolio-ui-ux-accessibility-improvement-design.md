# 포트폴리오 UI·UX·접근성 개선 설계

## 목표

채용 담당자가 첫 화면에서 지원 직무를 즉시 이해하고, 30~60초 안에 대표 작업과 경력을 훑은 뒤 프로젝트 상세와 연락까지 막힘없이 이동하게 한다. 현재 색상과 단순한 섹션 구조는 유지하며, 확인된 사용성 결함과 정보 위계만 최소 범위로 고친다.

직무 표기는 다음을 유지한다.

- 영문: `Frontend-focused Product Engineer`
- 국문: `프론트엔드 중심 프로덕트 엔지니어`

## 조사 범위와 근거

- 홈, 공통 레이아웃, 프로젝트 상세, 전역 CSS와 관련 테스트를 정적 검토했다.
- 첨부된 모바일 화면과 로컬 렌더링을 390px, 640px, 1024px에서 확인했다.
- 색 대비, 요소 크기, sticky header 높이와 anchor offset을 브라우저에서 측정했다.
- Uniport 문구는 `resume2026`의 career master, Claim/Evidence ledger, base career description을 교차검증했다.
- 1차 목록을 UI 시각 위계와 채용 UX·정보 구조 관점의 독립 서브에이전트 두 명에게 리뷰받았다.

## 1차 개선 목록

### 즉시 수정 후보

1. 이름보다 직무명이 먼저 읽히도록 히어로 위계를 변경한다.
2. 히어로의 강제 `<br>`을 제거하고 자연스러운 반응형 줄바꿈을 사용한다.
3. 전역 `overflow-wrap: anywhere`를 제거해 한글이 글자 단위로 끊기는 문제를 고친다.
4. 컨테이너의 폭 계산을 점검하고 불필요한 고정 폭을 제거한다.
5. 모바일 핵심역량 항목에 남는 홀수 카드의 오른쪽 보더와 부족한 padding을 고친다.
6. 히어로의 중복 문구와 과도한 세로 여백을 줄인다.
7. 경력 항목의 정보 밀도와 포맷을 통일하고 Uniport 기여를 추가한다.

### 추가 UI·UX·접근성 후보

8. 헤더·푸터 텍스트 링크의 터치 영역을 최소 44px로 확보한다.
9. sticky header 높이와 섹션 anchor offset을 맞춘다.
10. 본문 가독 폭을 점검한다.
11. 프로젝트 링크의 발견성과 클릭 영역을 높인다.
12. 연락 목적지와 실제 이메일 주소를 명확히 한다.
13. 홈 섹션의 스캔 순서를 검토한다.
14. 긴 프로젝트 상세에서 복귀 동선과 모바일 정보 밀도를 개선한다.
15. section과 heading의 접근 가능한 연결을 보강한다.
16. 주요 breakpoint에서 reflow, keyboard, zoom과 horizontal overflow를 검증한다.

## 서브에이전트 리뷰 결과

### 추가된 항목

- 모바일 2행 sticky header는 터치 영역 확대 후 화면을 더 많이 가리므로 40rem 이하에서는 sticky를 해제하는 편이 단순하고 안전하다.
- 상세 페이지 상단에 `← 대표 프로젝트` 복귀 링크가 필요하다.
- 상세 페이지는 모바일 전환 뒤에도 7개 섹션의 gap과 block padding이 커서 지나치게 길다.
- 홈에서 실제 작업이 약 3,000px 아래에 있어 추상적 역량보다 대표 프로젝트를 먼저 보여줄 필요가 있다.
- 상세 페이지의 결과가 너무 늦게 나오며 overview, problem, role, decisions에 유사 문장이 반복된다.
- Contact에 실제 이메일과 GitHub를 보여줘 메일 앱을 열지 않고도 주소를 복사할 수 있어야 한다.
- 선언만 있고 로드되지 않는 `Pretendard` 때문에 플랫폼별 줄바꿈과 굵기가 달라질 수 있다.
- 한국어 `.project-label`이 영문 eyebrow의 넓은 자간과 uppercase 규칙을 공유한다.
- 검색·공유 metadata도 이름보다 직무를 먼저 보여주는 전략과 맞춰야 한다.
- 현재 직무와 가장 가까운 Oprimed 작업이 대표 프로젝트에 없는 정보 공백이 있다.

### 제외하거나 축소한 항목

- `.shell`은 이미 `min(100% - gutter, max-width)` 방식의 유동 컨테이너다. 고정 px 폭이 줄바꿈 원인이라는 가설은 틀렸으므로 유지한다.
- 전역 본문 폭 재설계는 하지 않는다. hero와 case summary는 45rem, experience body는 46rem으로 이미 제한되어 있다.
- 프로젝트 링크는 밑줄·굵기·화살표가 있어 시각 발견성은 양호하다. 새 카드 디자인 대신 제목 링크와 44px 터치 영역만 보강한다.
- Uniport 기여 개수를 3개로 강제하지 않는다. 검증된 내용을 2개 bullet로 묶는다.
- 상세에 영문 eyebrow를 추가하지 않는다. 기존 `01–07` 번호 체계를 유지한다.
- 히어로 여백은 정보 구조를 바꾼 뒤 한 번만 조정한다.
- 새 아이콘, 그래픽, 캐러셀, 이전·다음 프로젝트 탐색은 추가하지 않는다.

## 최종 2차 개선 목록

### P0 — 현재 화면의 명확한 결함

#### 1. 히어로 직무 위계 재정렬

- 문제: 이름은 최대 5.75rem의 H1이지만 목표 직무는 작은 eyebrow와 보조 문장으로 반복된다.
- 변경: H1을 `프론트엔드 중심 프로덕트 엔지니어`로 바꾸고 `이수정`은 작은 보조 표기로 내린다. 영문 직무는 eyebrow로 유지한다.
- 변경: 직무 1줄, 차별점 1문장, 근거형 3항목으로 히어로 메시지를 압축한다.
- 변경: 강제 `<br>`을 제거하고 구조 변경 후에만 여백을 조정한다.
- 결과: 첫 5초 안에 지원 방향을 이해할 수 있다.

#### 2. 한글 단어 단위 줄바꿈 복구

- 문제: `body { overflow-wrap: anywhere; }`가 모든 텍스트에 적용되어 `넘/어`, `렌/더링`처럼 한글 단어가 임의 분해된다.
- 변경: 일반 한국어 콘텐츠에는 `word-break: keep-all`을 적용한다.
- 변경: URL이나 긴 기술 토큰처럼 실제 overflow 위험이 있는 요소에만 break 규칙을 국소 적용한다.
- 유지: `.shell`의 유동 폭 계산과 현재 gutter는 변경하지 않는다.

#### 3. 모바일 핵심역량 행 레이아웃 수정

- 문제: 1열 전환 뒤에도 `.strength-item:nth-child(odd)`의 높은 specificity 때문에 01·03 우측 보더가 남는다.
- 변경: 모바일 selector가 홀수 규칙을 확실히 덮도록 하고 모든 항목의 좌우 padding과 번호–본문 간격을 동일하게 만든다.
- 변경: 장식적 번호와 실제 내용의 읽기 순서는 유지한다. 별도 카드 컴포넌트는 만들지 않는다.

### P1 — 채용 UX와 탐색 개선

#### 4. 홈의 정보 순서 변경

- 문제: 현재 `Hero → Strengths → Experience → Projects` 순서에서는 검증 가능한 작업이 모바일 기준 약 3,000px 뒤에 나온다.
- 변경: `Hero → 대표 프로젝트 → 경력 → 핵심 역량 → Contact` 순서로 재배치한다.
- 변경: nav 순서도 화면 순서와 동일하게 맞춘다.
- 결과: 30~60초 훑기에서 주장보다 증거가 먼저 보인다.

#### 5. 경력 포맷과 Uniport 증거 밀도 통일

- 문제: Uniport만 `contributions`가 비어 최신 인접 경력이 한 줄로 보인다.
- 변경: 모든 경력을 `기간 / 회사 / 역할 / 요약 / 기여 목록`으로 동일하게 표시한다.
- Uniport 요약: `Mock API와 서버 상태를 바탕으로 문서·상태 관리 흐름을 구현하고, 데이터 조회와 업무 액션의 책임을 분리했습니다.`
- Uniport 기여 1: `테이블·검색·쿼리와 사용자 액션의 책임을 분리해 관리 화면을 구조화했습니다.`
- Uniport 기여 2: `역할·문서 상태별 액션을 구분하고 다운로드 오류와 도메인 범위 모달 상태를 처리했습니다.`
- 제외: 약 400줄에서 150줄로 줄였다는 검증되지 않은 수치.

#### 6. 헤더와 anchor 동작 정리

- 문제: 모바일 header는 약 94px인데 section `scroll-margin-top`은 80px이고, 링크 높이는 약 24px이다.
- 변경: nav와 footer 링크에 최소 44px hit area를 제공한다.
- 변경: 40rem 이하에서는 sticky header를 해제해 화면 점유와 anchor 가림 문제를 함께 제거한다.
- 유지: 데스크톱 sticky header와 현재 focus-visible 표현.

#### 7. 프로젝트 목록의 비교·진입 개선

- 문제: 제목은 클릭되지 않고 마지막 텍스트 링크만 진입점이며, 목록에서 결과를 비교하기 어렵다.
- 변경: 프로젝트 제목을 링크로 만들고 하나의 명확한 링크 구조만 유지한다.
- 변경: 링크에 최소 44px hit area와 기존 focus ring을 제공한다.
- 변경: 기존 `results[0]`을 짧은 검증 결과로 노출해 세 프로젝트를 비교할 수 있게 한다.

#### 8. 프로젝트 상세의 스캔과 복귀 개선

- 문제: 결과가 하단에 있고 유사 설명이 여러 섹션에서 반복되며 모바일 페이지가 약 4,000px 길다.
- 변경: hero 상단에 `← 대표 프로젝트` 링크를 추가한다.
- 변경: 상단에 기간, 역할, 핵심 문제, 검증 결과의 짧은 요약을 제공한다.
- 변경: 결과를 역할 다음으로 앞당기고 반복 문장을 삭제한다.
- 변경: 52rem 이하에서 `.case-section`의 gap과 block padding을 줄인다.
- 유지: 공개 범위와 생략 범위, 하단 복귀 링크, `01–07` 번호 체계.

#### 9. 연락 경로 명확화

- 문제: nav의 `연락`이 Contact로 이동하지 않고 즉시 mailto를 실행하며 실제 주소는 footer의 `Email` 텍스트 뒤에 숨는다.
- 변경: nav의 `연락`은 `/#contact`로 이동한다.
- 변경: Contact에 복사 가능한 이메일 주소와 GitHub 링크를 표시하고 mailto CTA는 유지한다.

#### 10. section label과 문서 제목 정렬

- 문제: Experience와 Contact section은 heading과 명시적으로 연결되지 않았고 metadata는 이름이 직무보다 먼저 나온다.
- 변경: 각 주요 section에 고유 heading id와 `aria-labelledby`를 연결한다.
- 변경: 기본·Open Graph title을 `Frontend-focused Product Engineer | 이수정` 순서로 통일한다.
- 유지: 단일 H1, 논리적인 H2/H3 구조, `lang="ko"`, skip link.

### P2 — 시각 일관성과 후속 콘텐츠

#### 11. 타이포와 상세 정렬 정리

- 한국어 `.project-label`을 영문 eyebrow의 uppercase·넓은 자간 규칙에서 분리한다.
- Pretendard를 실제로 로드하지 않을 경우 선언을 제거하고 현재 system font stack을 명시적으로 사용한다. 새 웹폰트 의존성은 추가하지 않는 쪽을 우선한다.
- tone section의 1.5rem 좌우 padding 때문에 생기는 기준선 차이만 통일한다.

#### 12. Oprimed 대표 사례 보강

- 문제: 현재 목표 직무와 가장 가까운 최신 Oprimed 경험이 대표 프로젝트에 없다.
- 방향: 별도 콘텐츠 작업으로 검증된 UI/API 조건 정렬, 복원·상태 전이, 차트 책임 분리 중 하나를 일반화한 사례를 추가하거나 가장 약한 프로젝트와 교체한다.
- 제약: 공개 근거 밖의 정량 성과, 내부 명칭, 화면과 코드는 추가하지 않는다.
- 이유: 이번 레이아웃·접근성 수정과 동시에 만들면 범위가 커지므로 별도 후속 작업으로 둔다.

## 유지할 요소

- 라벤더·민트·스카이·코럴의 제한된 팔레트와 border 중심 구분.
- 영문 eyebrow와 홈 section heading 체계, 상세의 `01–07` 번호 체계.
- 48px 이상의 primary/secondary CTA와 명확한 버튼 구분.
- skip link, 3px focus-visible ring, reduced-motion 대응.
- `lang="ko"`, landmark와 현재 heading 계층.
- 52rem의 주요 2열→1열 전환, 40rem의 flow 세로 전환과 화살표 방향 변경.
- 이미 AA를 충족하는 색 대비: muted/background 약 5.97:1, muted/mint 약 5.68:1, muted/sky 약 5.52:1, white/accent 약 8.08:1.

## 작업 계획

### 1단계 — P0 레이아웃 결함 수정

- 히어로 heading과 문구 구조를 바꾼다.
- 전역 줄바꿈 규칙을 국소 규칙으로 교체한다.
- 모바일 핵심역량 보더와 padding을 수정한다.
- 기존 홈 테스트를 새 heading 순서에 맞게 갱신한다.

완료 조건:

- 320px에서도 일반 한글 단어가 글자 단위로 임의 분해되지 않는다.
- 직무가 유일한 H1이고 이름보다 큰 시각 우선순위를 갖는다.
- 모바일 01·03 항목 오른쪽에 보더가 남지 않는다.
- horizontal overflow가 없다.

### 2단계 — 홈 스캔과 경력·연락 개선

- 홈 section과 nav 순서를 변경한다.
- Uniport 요약과 검증된 기여 2개를 추가한다.
- nav/footer hit area, 모바일 header, anchor 동작을 정리한다.
- 프로젝트 제목 링크, 결과 한 줄, Contact의 이메일·GitHub를 반영한다.
- section의 `aria-labelledby`와 metadata를 정리한다.

완료 조건:

- 키보드로 skip link → nav → CTA → 프로젝트 → Contact를 순서대로 이동할 수 있다.
- 모든 텍스트 링크의 클릭 영역이 최소 44×44 CSS px이거나 인접 대상과 충분히 떨어져 있다.
- nav의 `연락`이 Contact로 이동하고 이메일 주소를 읽고 복사할 수 있다.
- 세 경력 항목이 같은 포맷으로 렌더링된다.

### 3단계 — 프로젝트 상세 개선

- 상단 복귀 링크와 핵심 요약을 추가한다.
- 결과 순서를 앞당기고 반복 문구를 줄인다.
- 모바일 section gap·padding과 tone alignment를 조정한다.
- 상세 페이지 테스트에 상단 복귀와 새 section 순서를 반영한다.

완료 조건:

- 상세 진입 직후 프로젝트 목록으로 돌아갈 수 있다.
- 첫 화면 또는 첫 스크롤 안에 역할과 검증 결과를 파악할 수 있다.
- 모바일에서 불필요한 대형 공백 없이 7개 section을 스캔할 수 있다.

### 4단계 — 통합 검증

- `npm run lint`, `npm run test:run`, `npm run build`를 실행한다.
- 320, 390, 640, 641, 1024, 1440px에서 홈과 상세를 확인한다.
- 200% zoom과 키보드 탐색에서 clipping, 가림, focus 손실을 확인한다.
- 각 viewport에서 horizontal overflow, 한글 단어 분해, sticky/anchor 위치, hit area를 확인한다.

## 비목표

- 새 디자인 시스템, 컴포넌트 추상화, 의존성, 이미지, 애니메이션을 추가하지 않는다.
- `.shell` 컨테이너나 전체 팔레트를 교체하지 않는다.
- 검증되지 않은 경력 수치나 내부 정보를 추가하지 않는다.
- 이번 작업에서 Oprimed 사례를 즉시 작성하지 않는다. 별도 콘텐츠 검증 작업으로 진행한다.
