# Git 이름 규칙 설계

## 목적

브랜치, 커밋, PR 제목이 같은 변경 범주와 짧은 설명을 사용하도록 통일한다.

## 규칙

- 브랜치: `<type>/<kebab-case-설명>`
- 커밋: `<type>: <한국어 명령형 설명>`
- PR 제목: `[<type>] <한국어 설명>`
- 허용 `type`: `feat`, `fix`, `refactor`, `docs`, `test`, `chore`, `ci`, `deploy`
- `feat`, `fix`, `refactor`에는 기능 또는 사용자 영향의 핵심을 적고, 나머지는 작업 대상을 적는다.

## 문서 위치와 범위

- 저장소 루트에 `CONTRIBUTING.md`를 추가한다.
- 복잡한 자동 검사나 커밋 도구는 도입하지 않는다. 팀이 즉시 복사해 쓸 수 있는 예시와 PR 템플릿만 제공한다.

## 검증

- 예시는 허용 타입·형식과 일치해야 한다.
- 문서 안의 브랜치, 커밋, PR 예시가 동일한 변경을 일관되게 설명해야 한다.
